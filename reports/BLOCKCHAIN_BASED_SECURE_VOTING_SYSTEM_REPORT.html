ABSTRACT

Electronic voting platforms represent the vanguard of modern democratic engagement but frequently suffer from critical vulnerabilities including duplicate ballot injection, centralized administrative database tampering, and voter privacy compromise. This academic project presents the design and implementation of the "BLOCKCHAIN-BASED SECURE VOTING SYSTEM", a secure, full-stack, and user-centric platform tailored for collegiate and organizational governance under the tagline "Your Vote. Your Voice. Securely."

The architecture bridges a normalized relational Database Management System (3NF schema) with a custom SHA-256 hash-linked cryptographic ledger. Voter eligibility and identity verification are mathematically decoupled from cast ballots, ensuring complete ballot anonymity while strictly enforcing the fundamental "one vote per eligible voter" constraint through database-level transactions. Each accepted ballot is mined into an append-only block containing the preceding block's cryptographic hash, enabling real-time verification and immediate detection of unauthorized data modifications.

Furthermore, the project delivers an advanced user experience featuring a high-contrast White Mode interface by default, instant Dark Mode toggling, and an integrated AI Voice Assistant powered by the Web Speech API capable of voice navigation, manifesto readout, and real-time ledger verification audits.

Keywords: Relational DBMS, 3NF Normalization, Blockchain Ledger, SHA-256 Hash Linking, Anonymous Ballot, AI Voice Assistant, White Mode UI, ACID Transactions, Antigravity Workspace.

1.2 Motivation and Relevance

Collegiate elections, departmental councils, and institutional governance require both accessibility and unquestionable auditability. Paper ballots are prone to logistical delays, manual miscounts, and tampering. Conversely, centralized databases can be manipulated internally by superusers without leaving traces. The proposed system pairs relational constraints with cryptographic chaining so that any retroactive modification immediately breaks the mathematical pointer links.

1.3 Problem Statement

Traditional electronic voting systems suffer from three critical shortcomings: (1) Ballot trace-backs compromising voter privacy, (2) Vulnerability to covert row manipulation by database administrators, and (3) Fixed, non-accessible user interfaces without voice or multimodal assistance.

1.4 Objectives of the Project

1. Design and implement a 3NF normalized relational schema encompassing users, elections, candidates, voter_eligibility, votes, blockchain_blocks, and audit_logs.
2. Prevent duplicate votes at the database engine level using ACID transactions and unique constraints.
3. Build an append-only SHA-256 cryptographic ledger with genesis block initialization.
4. Develop a radiant White Mode user interface with Dark Mode switching and Web Speech AI Voice Assistant.

CHAPTER 3: SYSTEM DESIGN & DATABASE ARCHITECTURE

3.1 3NF Normalization Analysis

• 1NF: All attributes contain atomic values. Surrogate primary keys are assigned to each table.
• 2NF: Full functional dependency on primary keys. Associative tables (e.g., candidate mapping) eliminate partial key dependencies.
• 3NF: Elimination of transitive dependencies. The votes table records only candidate_id and block_id; candidate names, party affiliations, and voter names are stored exclusively in their respective tables.

3.2 Anonymous Ballot Protocol

When voter Alex Rivera votes for Dr. Elena Vance: (1) An atomic transaction verifies that is_eligible = 1 and has_voted = 0 in voter_eligibility. (2) has_voted is set to 1. (3) A new vote row is inserted with only candidate_id and an encrypted token. (4) A cryptographic block is mined linking to block #0. (5) The transaction commits. Voter identity is completely decoupled from the candidate choice!

3.3 Cryptographic Hash Linking (SHA-256)

Each block calculates its current hash using: 

current_hash = SHA256(election_id + ":" + block_index + ":" + previous_hash + ":" + tx_hash + ":" + timestamp);

Verification re-executes this function across all blocks in order. If any previous hash or payload is altered, verification fails immediately.
